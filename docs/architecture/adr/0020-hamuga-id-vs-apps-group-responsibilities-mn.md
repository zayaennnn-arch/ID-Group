# ADR-0020: Hamuga ID ба апп-уудын үүргийн хуваарь. Баталгаажсан байгууллага, эцэг/эх–хүүхдийн холбоо ID-д; гэр бүл, найз, бусад групп ба байршил хуваалцах газрын зургийн апп-д; бизнесийн цэг POI engine-д; байгууллагын нэрээр төлбөр төлбөрийн системд

- **Статус:** хүлээн авсан (PO 2026-10-27, «Тийм, шилжүүл»). **Нэмэлт өөрчлөлт A1 (PO 2026-10-28):** гэр бүлийн групп Hamuga ID-д үлдэнэ; газрын зургийн апп нь **iMap**, цэсийн нэр «Групп» (О1, О2 хаагдсан). A1 нь доорх Шийдвэрийн 2, 4-ийг давамгайлна.
- **Огноо:** 2026-10-27
- **Хэрэглэгчийн түүхүүд:**
  - Хамаарах: NAV-024 … NAV-032.
  - Шинэ: NAV-033 (апп-ын групп, байршил хуваалцах), NAV-034 (хүүхдийн байршлын горим), NAV-035 (ID → апп-уудад өгөх API, байгууллагын горим).
- **Нотолгоо:**
  - [Yandex, 2ГИС, Kakao-ийн судалгаа](../spikes/yandex-2gis-groups-location-research-mn.md)
  - [SSO дээрх группийн судалгаа](../spikes/group-org-sso-research-mn.md)
  - [Процессын зураглал](../../requirements/process-map-group-org-mn.md)
- **Гэрээ:** `openapi.yaml` өөрчлөгдөхгүй. ID-ийн API нь ICT Group-ийн гэрээ. Манай gateway-ээр дамжих эсэхийг ADR-0007-ийн дагуу NAV-035-д шийднэ.
- **Босго:** D38. Hamuga-тай холбоотой story-ууд ICT Group-ийн бичгэн гэрээгүйгээр `ready` болохгүй.

## Нөхцөл байдал

«Групп, байгууллагын бүртгэл» эпикийг анх **бүхэлд нь Hamuga ID дээр** гэж задалсан:
- NAV-024: 4 төрлийн групп;
- NAV-030 A: байршил хуваалцах;
- прототипын «Миний групп» хуудас.

PO 2026-10-27-нд «эдгээр зорилгод хүрэхийн тулд бүх группыг ID дээр бүртгэх нь зөв үү?» гэж асуусан.

Судалгааны гол олдворууд:
1. **Байгууллага identity түвшинд байна.**
   - Yandex-ийн «Организации в ID»-ийн мэдээллийг Pay, Market, «Yandex ID for websites» зэрэг олон үйлчилгээ дахин ашигладаг.
   - Microsoft Entra, Google Workspace, Singapore Corppass ч мөн адил.
   - Yandex-ийн role (Эзэмшигч, Админ, Гишүүн; Админ бусад админыг засахгүй) манай NAV-027-той ижил.
2. **Байршил хуваалцах функц нэг ч платформд identity системд байдаггүй.**
   - Yandex-д Карты апп (2026 оны 1-р сараас), 2ГИС-д газрын зургийн апп.
   - Kakao-д мессенжер, Apple-д Find My, Google-д Maps.
3. **Найз, бусад групп апп дотор байна.** 2ГИС, Kakao, Life360.
4. **Identity түвшний «Гэр бүл»** (Yandex, Apple, Google) нь **захиалга, төлбөр хуваалцах** зорилготой. Байршил хуваалцдаггүй.
5. **Газрын зураг дээрх бизнесийн цэг тусдаа системд байна.** Yandex-д Yandex Бизнес. Баталгаажуулалт нь цэгийн утас руу код (NAV-032-той ижил).

Хязгаарлалтууд:
- Hamuga ID нь ICT Group-ийн **бүх** апп ашигладаг SSO. Түүнд нэг апп-ын онцлог функц орвол бүх апп нэг хувилбарын мөчлөгт уягдана.
- Бодит цагийн байршил бол хувийн мэдрэмтгий мэдээлэл. Identity систем үүнийг хадгалах шаардлагагүй.
- Байгууллагыг баталгаажуулах ажил ДАН + ХУР-аас хамаарна (NAV-029). Энэ нь identity-ийн ажил.
- Эцэг/эх–хүүхдийн холбоо ДАН-аар нотлогдож **ID-д аль хэдийн байгаа** («Миний хүүхэд»).

## Шийдвэр

### 1. Үүргийн дүрэм
**ID нь «хэн бэ, хэнийг төлөөлдөг вэ»-г, апп нь «юу хийх вэ»-г хариуцна.** ID-д дараах **гурван** шинжийн аль нэг нь байх өгөгдөл л орно:
- төрийн эх сурвалжаар (ДАН, ХУР) нотлогддог;
- олон апп дахин ашигладаг;
- хууль, аюулгүй байдлын хариуцлагатай (хэн байгууллагыг төлөөлдөг).

### 2. Систем тус бүрийн хариуцлага

| Систем | Хариуцах зүйл | Хариуцахгүй зүйл |
|---|---|---|
| **Hamuga ID** | Байгууллага бүртгэх, баталгаажуулах (ДАН + ХУР); байгууллагын гишүүнчлэл, role (Эзэмшигч, Админ, Гишүүн); байгууллагын контакт, ажлын имэйлийн домэйн; эцэг/эх–хүүхдийн холбоо; эдгээрийг апп-уудад өгөх API, token claim | Найз, бусад, гэр бүлийн групп; байршил; бизнесийн цэг; төлбөр |
| **Газрын зургийн апп** (О1) | Гэр бүл, найз, бусад групп; урих, хасах; байршил хуваалцах; хүүхдийн байршлын горим | Байгууллага баталгаажуулах; эцэг/эх–хүүхдийн холбоог тогтоох |
| **Hamuga POI engine / бизнес кабинет** | Бизнесийн цэг өмчлөх, засах, менежер; байгууллагын POI | Байгууллагын баталгаажуулалт (ID-аас асууна) |
| **Төлбөрийн систем** | Байгууллагын нэрээр төлөх | Хэн төлөх эрхтэйг тогтоох (ID-аас асууна) |

### 3. ID → апп-уудын гэрээ (NAV-035)
1. **Token claim** (OIDC):
   - `org_id`, `org_role` нь хэрэглэгч «байгууллагын горим»-оор нэвтэрсэн үед л очно;
   - `dan_level`.
2. **API:**
   - хэрэглэгчийн байгууллагууд ба role;
   - байгууллага баталгаажсан эсэх;
   - хэрэглэгчийн ДАН-аар холбогдсон хүүхдүүд (нас, ID, `scope`-оор хязгаарласан);
   - өөрчлөлтийн мэдэгдэл (webhook): гишүүн хасагдсан, хүүхэд 18 нас хүрсэн, байгууллагын удирдлага солигдсон.
3. **Байгууллагын горим:**
   - хэрэглэгч ID-ийн профайлаас байгууллагаа сонгож, байгууллагын нэрээр апп-уудад нэвтэрнэ (Yandex загвар);
   - хувийн горим руу буцаж болно.

### 4. Апп-ын групп (NAV-033, NAV-034)
- **Төрөл:** «Гэр бүл», «Найз», «Бусад». **«Байгууллага» төрөл апп-д байхгүй.** Апп байгууллагын жагсаалтыг ID-аас уншина.
- **Эрх:** NAV-027-ийн матрицын «Гэр бүл», «Найз», «Бусад» баганыг апп хэрэгжүүлнэ. «Байгууллага» баганыг ID хэрэгжүүлнэ.
- **Хүүхэд нэмэх:** «Гэр бүл» группт хүүхдийг урилгагүйгээр нэмнэ. Хүүхдийн жагсаалтыг ID-ийн API-аас (§3) авна. Апп эцэг/эх–хүүхдийн холбоог өөрөө тогтоохгүй.
- **Байршил хуваалцах** (судалгаа §6.2):
  - анхдагчаар унтраалттай;
  - хугацаатай: 15 минут, 1 цаг, 8 цаг, 24 цаг, эсвэл зогсоох хүртэл;
  - харилцан зөвшөөрөлтэй;
  - группээр нь түр нуух боломжтой;
  - апп-гүй хүнд хөтөч дээр нээгдэх холбоос.
- **Хүүхдийн горим:** хүүхэд эцэг/эхээс байршлаа нууж чадахгүй.
  - Насны хязгаарыг ID-ийн насны дүрмээр тогтооно: 0–16 нь эцэг/эхийн хяналтад.
  - 18 нас хүрэхэд ID-ийн webhook-оор хяналт унтарч, хүүхдээс дахин зөвшөөрөл асууна.

### 5. Бизнесийн цэг ба төлбөр
- NAV-032 POI engine / бизнес кабинетэд хэрэгжинэ. ID зөвхөн ДАН Level 2-ыг баталгаажуулна. «Байгууллагад шилжүүлэх» (AC 16) нь ID-ийн байгууллагыг §3-ын API-аар уншина.
- NAV-030 C ба NAV-031 төлбөрийн системд хэрэгжинэ. Төлөх эрхийг ID-ийн `org_role`-оор шалгана.

### 6. Нээлттэй

| # | Асуулт | Санал | Хэн |
|---|---|---|---|
| О1 | Газрын зургийн апп нь **Hamuga Map** уу, **Nav** уу? | Хоёулаа ашиглах бол групп, байршлын backend-ийг **Hamuga-ийн нэг үйлчилгээ** болгож, хоёр клиент дуудна. Ингэхгүй бол групп хоёр апп-д давхардана | PO / ICT Group |
| О2 | ID-д захиалга, төлбөр хуваалцах «Гэр бүл» хэрэгтэй юу? | Одоогоор **үгүй**. Hamuga-д хуваалцах захиалга гарвал тусдаа story болгоно | PO |

## Харгалзсан хувилбарууд

| Хувилбар | Давуу тал | Сул тал |
|---|---|---|
| **A. Бүх групп, байршил ID-д** (анхны задаргаа) | Нэг газар; прототип бэлэн | ID томорч, бүх апп нэг хувилбарын мөчлөгт уягдана; ID байршил хадгална (нууцлалын эрсдэл); аль ч платформ ингэдэггүй |
| **B. Үүргийг хуваах** (сонгосон) | ID зөвхөн нотлогдсон, дахин ашиглах мэдээлэлтэй; байршлыг апп бие даан хөгжүүлнэ; Yandex, 2ГИС, Apple, Google-ийн загвартай ижил | ID → апп API (NAV-035) нэмэгдэнэ; хоёр багийн хамтын ажиллагаа шаардлагатай |
| **C. Бүгд апп-д, ID-д юу ч нэмэхгүй** | ID өөрчлөгдөхгүй | Байгууллагын баталгаажуулалт апп бүрт давхардана; бусад апп «энэ хүн X байгууллагыг төлөөлдөг» гэдгийг мэдэхгүй; SSO-ийн давуу тал алга болно |

## Үр дагавар
- **ID-ийн эпик жижгэрнэ:** NAV-024 (зөвхөн байгууллага), NAV-025, NAV-026 (байгууллагын гишүүнчлэл), NAV-027 (байгууллагын багана), NAV-028, NAV-029, NAV-035. ДАН/ХУР-ын интеграцтай, хамгийн эрсдэлтэй хэсэг нэг багт төвлөрнө.
- **Апп-ын шинэ ажил:** NAV-033, NAV-034. Энэ ажил NAV-035 (хүүхдийн жагсаалт) ба О1-ийн шийдвэрээс хамаарна.
- **NAV-030** нь B (POI) ба C (төлбөр) болж нарийсна. A нь NAV-033 руу шилжинэ.
- **Прототип (2026-10-27-нд хийсэн):** `NAV-024-groups.html` нэг файл дотор хоёр системтэй. Дээд талын «ПРОТОТИП · Систем» сэлгүүрээр Hamuga ID («Миний байгууллага», байгууллагын горим) ба газрын зургийн апп («Группууд», газрын зураг, байршил хуваалцах) хооронд шилжинэ. `?sys=app` нь апп талыг шууд нээнэ.
- **Процессын зураглал:** процесс бүрт систем тэмдэглэсэн. P1 ба P8 A нь апп руу, P7 POI руу шилжинэ.
- **Хүлээн зөвшөөрсөн эрсдэл:** ID ба апп хоёр багийн хооронд гэрээ (§3) тогтворгүй бол апп-ын ажил саатна. NAV-035-ыг апп-ын story-уудаас **өмнө** хийнэ.

## Нэмэлт өөрчлөлт A1 (PO 2026-10-28): гэр бүл ID-д, апп нь iMap

PO-ийн шийдвэр:
1. «Гэр бүл» групп **Hamuga ID-д** үлдэнэ. ID-ийн «Гэр бүл» цэсэнд гишүүд, ДАН-аар холбогдсон хүүхдүүдийг удирдана.
2. Газрын зургийн апп нь **iMap** (О1 хаагдсан). iMap-ын шинэ цэс **«Групп»**.
3. iMap гэр бүлийн группыг ID-аас уншиж, хэрэглэгч тэр группт **байршлаа хуваалцана**. Гишүүдийг iMap-аас өөрчлөхгүй, «Hamuga ID-д удирдах» холбоосоор ID руу шилжинэ.

| Систем | A1-ийн дараах хариуцлага |
|---|---|
| **Hamuga ID** | Байгууллага (NAV-024, NAV-026–NAV-029), **гэр бүлийн групп** (NAV-024 B), эцэг/эх–хүүхдийн холбоо, NAV-035-ын API |
| **iMap** («Групп» цэс) | Найз, бусад групп үүсгэх, удирдах; **бүх группт** (гэр бүлийг оруулаад) байршил хуваалцах; хүүхдийн горим (NAV-033, NAV-034) |

Шалтгаан: гэр бүл нь ДАН-аар нотлогдсон эцэг/эх–хүүхдийн холбоонд тулгуурладаг. Мөн Hamuga-ийн бусад үйлчилгээ ч (жишээ нь ирээдүйд захиалга хуваалцах) гэр бүлийг ашиглаж болно. Иймд Шийдвэр 1-ийн «олон апп дахин ашигладаг» шалгуурт нийцнэ (Yandex ID-ийн «Семья», Apple, Google-ийн загвар).

Үр дагавар:
- NAV-035 нь гэр бүлийн группуудыг гишүүдтэй нь буцаана.
- NAV-033 нь найз, бусад группт нарийсч, байршил хуваалцах нь бүх группт хамаарна.
- О2 («захиалга хуваалцах гэр бүл») энэ шийдвэрт шингэсэн.
- Прототип: Hamuga ID-д «Гэр бүл» ба «Миний байгууллага» цэс, iMap-ын загвар (зүүн талын icon цэс, «Групп» самбар, бодит Hamuga газрын зураг `hamuga-imap-sdk@0.1.1`) нэмэгдсэн.
- **API түлхүүрийг repo-д хадгалахгүй.** Прототип түлхүүрийг `imap-key.local.js` (git-д ордоггүй), `?key=…` эсвэл хөтчид хадгалсан утгаас уншина (ADR-0007-ийн зарчим).
