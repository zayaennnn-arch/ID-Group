# Процессын зураглал — «Групп, байгууллагын бүртгэл» эпик

> Огноо: 2026-10-27, шинэчилсэн 2026-11-02 · Хариуцагч: business-analyst · Төлөв: draft (D38: Hamuga-тай бичгээр тохиролцох хүртэл)
> Эх сурвалж: NAV-024 … NAV-035, [ADR-0020 + A1](../architecture/adr/0020-hamuga-id-vs-apps-group-responsibilities-mn.md), [судалгаа](../architecture/spikes/group-org-sso-research-mn.md), [прототип](../design/prototypes/NAV-024-groups.html)
> Зорилго: эпикийн **бүх үйлдлийг** нэг дор, хэн (оролцогч) ямар системтэй (ДАН, POI engine гэх мэт) харилцаж байгааг харуулах. AC-ийн дугаар бүр тухайн story-д заагдсан.

## 0. Оролцогчид ба системүүд

| Оролцогч / систем | Үүрэг |

## 1. Ерөнхий зураглал

Хэрэглэгч группын **төрөл сонгохгүй**: аль цэснээс эхэлж байгаа нь төрлийг тодорхойлно (Hick, Tesler: сонголтыг систем хариуцна).

**Систем ([ADR-0020 + A1](../architecture/adr/0020-hamuga-id-vs-apps-group-responsibilities-mn.md)):** ID нь «хэн бэ, хэнийг төлөөлдөг вэ, хэн хэний гэр бүл вэ»-г, апп нь «юу хийх вэ»-г хариуцна. Тасархай шугам нь системийн хоорондох гэрээ (P9).

## 2. P1 — Гэр бүл (Hamuga ID) ба Групп (iMap) үүсгэх

> ADR-0020 A1 (2026-10-28): «Гэр бүл»-ийг Hamuga ID-ийн «Гэр бүл» цэсэнд үүсгэж удирдана. Найз, баг, клубыг iMap-ын «Групп» цэсэнд **нэг төрлөөр** үүсгэнэ (PO 2026-10-28: «ижил төрлийн групп учраас сонгуулах шаардлагагүй»). iMap гэр бүлийг NAV-035-аар уншиж, байршил хуваалцана.

### 2.1 P1a — Гэр бүл үүсгэх (Hamuga ID, NAV-024 B)

```mermaid
flowchart TD
    S(["Hamuga ID → «Гэр бүл» → «Гэр бүл үүсгэх»"]) --> F1["Нэр: «Манай гэр бүл» бэлэн бичигдсэн<br/>1–50 тэмдэгт"]

    F1 --> K{"«Миний хүүхэд»-д<br/>ДАН-аар холбогдсон<br/>хүүхэд байгаа юу?"}
    K -- "Тийм" --> K1["Хүүхдүүдийг сонгох<br/>урилгагүйгээр нэмэгдэнэ"]
    K -- "Үгүй" --> K2["«Миний хүүхэд» → «Хүүхэд бүртгэх»<br/>Hamuga ID-ийн одоогийн процесс"]
    K2 --> KA{"Хүүхдийн нас"}
    KA -- "0–16" --> KP["Хүүхэд хүсэлт илгээнэ →<br/>эцэг/эх 10 минутад зөвшөөрнө"]
    KA -- "16–18" --> KS["Хүүхэд ДАН эсвэл<br/>E-Mongolia кодоор өөрөө"]
    KP --> K1
    KS --> K1
    K1 --> SAVE["«Үүсгэх»"]
    SAVE --> R(["Гэр бүл үүснэ,<br/>үүсгэгч = Эзэмшигч"])
    R --> I["Насанд хүрсэн гишүүдийг урих<br/>утас / имэйл → P4a"]
    R -. "NAV-035 webhook" .-> IMAP(["iMap-ын «Групп» жагсаалтад<br/>«Hamuga ID» тэмдэгтэй гарна"])
```

- Хүүхэд урилга зөвшөөрөх шаардлагагүй: эцэг/эх ба хүүхдийн холбоо ДАН-аар аль хэдийн баталгаажсан (судалгаа §3.3).
- Хүүхэд 18 нас хүрэхэд группт **насанд хүрсэн гишүүн** болж үлдэнэ. Эцэг/эхийн хяналт (байршил гэх мэт) дахин зөвшөөрөл шаардана.
- Гэр бүлийн гишүүнийг iMap-аас урих, хасах **боломжгүй**: iMap «Hamuga ID-д удирдах» холбоосоор ID-ийн тэр группыг нээнэ.

### 2.2 P1b — Групп үүсгэх (iMap, NAV-033 A)

```mermaid

    S(["iMap → «Групп» → «Групп үүсгэх»"]) --> N["Ганц талбар: нэр<br/>санал болгох нэрс: «Найзууд», «Баг», «Аялал»"]

    R --> INV["«Гишүүн нэмэх» цонх шууд гарна:<br/>QR · холбоос хуулах · «Хуваалцах»"]
```

- Хязгаар: нэг хэрэглэгч 20 групп; гэр бүл 20 гишүүн; **«Групп» гишүүний хязгаар Б8** (найз 50 / бусад 100 нэгдсэн тул PO шийднэ).

### 3.2 Регистр, ТТД-ийг ХУР-аас хэрхэн шалгах вэ (системийн дараалал)

**ДАН ба ХУР:** ДАН нь хэрэглэгчийг таньж, нэвтэрсэн иргэний регистрийг өгнө. Байгууллагын мэдээлэл ХУР-ын (`xyp.gov.mn`) сервисүүдээс ирнэ.

**`WS100818_taxPayerInfo`-ийн гэрээ (Татварын ерөнхий газар, v1.5.0, ICT Group 2026-10-27):**

| | Талбар | Тайлбар | Төрөл |
|---|---|---|---|
| Оролт | `pin` | Татвар төлөгчийн регистрийн дугаар | String |
| Оролт | `tin` | Татвар төлөгчийн дугаар (ТТД) | String |
| Гаралт | `listTins[]` | Татвар төлөгчийн **жагсаалт** | List |
| Гаралт | `listTins[].tin` | ТТД | String |
| Гаралт | `listTins[].name` | Татвар төлөгчийн нэр | String |

Үүнээс гарах дүгнэлт:
- Нэг регистрт **хэд хэдэн** татвар төлөгч байж болох тул оруулсан ТТД-г жагсаалтын **аль нэг**-тэй тулгана.
- `name` буцаадаг тул хувиараа бизнес эрхлэгчийн «Энэ байгууллага мөн үү?» дэлгэцэд нэрийг харуулж болно.
- Гаралтад **удирдлага, төрөл, төлөв байхгүй**. Хуулийн этгээдийн удирдлагыг тодорхойлоход хуулийн этгээдийн сервис (Б1) хэрэгтэй хэвээр. Хувиараа бизнес эрхлэгч идэвхтэй эсэхийг энэ сервисээр мэдэхгүй (Б6).

**Дугаарыг хэлбэрээр нь ялгана** (дараалан оролдохгүй; хэрэглэгчээс төрлийг асуухгүй):

| Оруулсан утга | Гэж үзэх | Дуудах сервис | Тулгалт |
|---|---|---|---|
| 7 орон | Хуулийн этгээдийн регистр (хуулийн этгээдийн ТТД = регистр гэж үзнэ, Б2) | ХУР: хуулийн этгээдийн мэдээлэл | Удирдлагын регистр = нэвтэрсэн иргэний регистр → шууд; үгүй бол удирдлагын зөвшөөрөл |
| Бусад урттай тоо | Иргэний ТТД (хувиараа бизнес эрхлэгч) | `WS100818_taxPayerInfo`, `pin` = **нэвтэрсэн иргэний** регистр | Оруулсан утга ∈ `listTins[].tin` → шууд; үгүй бол «таны нэр дээр бүртгэлгүй» |
| 2 үсэг + 8 орон | Иргэний регистр | `WS100818_taxPayerInfo`, `pin` = оруулсан утга, **зөвхөн** нэвтэрсэн иргэнийх бол | Өөр хүний регистр бол «Өөрийн регистр эсвэл байгууллагын регистрийг оруулна уу» |

> **Хувийн мэдээллийн дүрэм (AC 16):** `WS100818_taxPayerInfo`-ийн `pin`-д зөвхөн ДАН-аар нэвтэрсэн хэрэглэгчийн **өөрийн** регистрийг дамжуулна. Хэрэглэгчийн бичсэн өөр хүний регистрээр ТТД, нэр лавлахгүй.

```mermaid
sequenceDiagram
    autonumber
    actor U as Хэрэглэгч
    participant DAN as ДАН
    participant H as Hamuga ID backend
    participant LE as ХУР: хуулийн этгээдийн мэдээлэл
    participant TX as ХУР: WS100818_taxPayerInfo
    actor D as Хариуцах иргэн

    U->>DAN: Нэвтрэх, Level 2
    DAN-->>H: Иргэний регистр сессэд
    U->>H: «Байгууллага бүртгэх» нээв
    H->>TX: pin = иргэний өөрийн регистр
    TX-->>H: listTins = [{tin, name}, ...]
    H-->>U: «Таны нэр дээрх татвар төлөгч» сонголтууд, AC 14
    alt Сонголтоос нэгийг дарав
        H-->>U: «Энэ байгууллага мөн үү?» + name → «Бүртгэх» → шууд баталгаажна
    else 7 оронтой регистр бичсэн
        H->>LE: Хуулийн этгээдийн регистрээр хайх
        LE-->>H: Албан ёсны нэр, төлөв, удирдлагын регистр
        H->>H: Идэвхтэй эсэх, давхардал AC 10, удирдлага = иргэн эсэх
        alt Хэрэглэгч = удирдлага
            H-->>U: «Бүртгэх» → «Баталгаажсан байгууллага», Эзэмшигч
        else Хэрэглэгч ≠ удирдлага
            U->>H: «Удирдлагаас зөвшөөрөл хүсэх»
            H->>D: Push / SMS / имэйл, 72 цаг
            D->>DAN: Нэвтрэх
            DAN-->>H: Регистр = удирдлагын регистр эсэх
            D->>H: «Зөвшөөрөх» + Эзэмшигч / Админ сонгох
            H-->>U: «Баталгаажсан байгууллага»
        end
    else ТТД бичсэн
        H->>H: Бичсэн ТТД ∈ listTins[].tin эсэх, алхам 5-ын хариугаар
        alt Байгаа
            H-->>U: «Энэ байгууллага мөн үү?» + name → шууд баталгаажна
        else Байхгүй
            H-->>U: «Энэ ТТД таны нэр дээр бүртгэлгүй байна», AC 15
        end
    end
    Note over H: Хадгалах: регистр/ТТД, албан ёсны нэр,<br/>хариуцах иргэний таних тэмдэг л, AC 12
```

|---|---|---|---|---|
| ХХК, ХК, ТББ, сан, холбоо, төрийн байгууллага | Хуулийн этгээдийн регистр (7 орон) | Гүйцэтгэх удирдлага | Хуулийн этгээдийн мэдээлэл | Удирдлагын регистр = нэвтэрсэн иргэний регистр |

| Гадаадын байгууллагын салбар | Хуулийн этгээдийн регистр | Монгол дахь удирдлага | Хуулийн этгээдийн мэдээлэл | Удирдлага ДАН-гүй бол баталгаажихгүй (R3, хүлээн зөвшөөрсөн) |

Хувиараа бизнес эрхлэгчид «Удирдлагаас зөвшөөрөл хүсэх» зам **байхгүй**: татвар төлөгч нь иргэн өөрөө тул ТТД таны регистр дээр байхгүй бол өөр хэн нэгнээс зөвшөөрөл авах шаардлагагүй.

### 3.3 Баталгаажсаны дараах хяналт

- **Сар бүрийн тулгалт (AC 13):** ХУР-аас хуулийн этгээдийн мэдээллийг дахин татаж удирдлага солигдсон эсэхийг шалгана. Солигдсон бол хуучин удирдлагаар баталгаажсан Эзэмшигчийн эрх «Хүлээгдэж буй» болж, шинэ удирдлага руу зөвшөөрлийн хүсэлт автоматаар очно.
- Олон хариуцах иргэнтэй бол аль нэг нь зөвшөөрөхөд хангалттай.
- Хассан аргууд: видео, баримт бичиг, операторын хяналт, тоон гарын үсэг, данснаас шилжүүлэг (P5).
