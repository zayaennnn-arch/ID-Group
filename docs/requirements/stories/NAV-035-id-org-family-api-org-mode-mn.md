# NAV-035: ID → апп-уудын гэрээ ба байгууллагын горим

## Story
**Hamuga-ийн апп** (газрын зураг, POI кабинет, төлбөр) миний хувьд **хэрэглэгч ямар байгууллагыг ямар role-оор төлөөлдөг, ямар хүүхдүүдтэй ДАН-аар холбогдсоныг ID-аас найдвартай авахыг** хүсч байна, ингэснээр **баталгаажуулалтыг апп бүрт давтахгүйгээр байгууллагын нэрээр үйлдэл хийх, гэр бүлд хүүхэд нэмэх** боломжтой болно.

Хоёрдогч persona: **байгууллагын ажилтан** профайлаасаа байгууллагаа сонгож, бүх апп-д байгууллагын нэрээр нэвтэрнэ.

## Нөхцөл байдал
Эх сурвалж:
- [ADR-0020](../../architecture/adr/0020-hamuga-id-vs-apps-group-responsibilities-mn.md) §3;
- [судалгаа §2.1, §6.3](../../architecture/spikes/yandex-2gis-groups-location-research-mn.md): Yandex-ийн «байгууллагын горим».

Манай backend-ээс ID-ийн API руу хандах эсэх, хэрхэн хандахыг ADR-0007-ийн дагуу (gateway-ээр) architect шийднэ.

### Хэрэглэгчид харагдах string-үүд
- «Хувийн», «Байгууллагын нэрээр», «Байгууллага солих», «Хувийн горим руу буцах»

## Хүлээн авах шалгуур (AC)

### A. Token claim
1. **Өгөгдсөн нь** хэрэглэгч «байгууллагын горим»-оор нэвтэрсэн, **Тэгвэл** ID token-д `org_id`, `org_role` (`owner` / `admin` / `member`), `org_verified` очно. Хувийн горимд эдгээр claim **очихгүй**.
2. Бүх token-д `dan_level` очно.

### B. API
3. `GET` хэрэглэгчийн байгууллагууд: `org_id`, нэр, `verified`, `role`. Хэрэглэгч `scope`-оор зөвшөөрсөн апп л уншина.
4. `GET` хэрэглэгчийн ДАН-аар холбогдсон хүүхдүүд: ID, нэр, **насны бүлэг** (0–16 / 16–18). Төрсөн огноо бүтнээр очихгүй. Тусдаа `scope`, эцэг/эх тухайн апп-д зөвшөөрнө.
5. `GET` байгууллага баталгаажсан эсэх, тухайн хэрэглэгчийн role (POI кабинет, төлбөрийн системд).
6. **Webhook:** гишүүн хасагдсан, гарсан, role солигдсон; байгууллагын баталгаажуулалт цуцлагдсан (NAV-029 AC 13); хүүхэд 16 эсвэл 18 нас хүрсэн; эцэг/эх–хүүхдийн холбоо салсан.
7. Бүх хандалт аудитын логт (аль апп, ямар `scope`, хэзээ) бичигдэнэ.

### C. Байгууллагын горим
8. **Өгөгдсөн нь** нэг буюу хэд хэдэн байгууллагын гишүүн, **Хэзээ** ID-ийн профайл цэсийг нээхэд, **Тэгвэл** «Хувийн» ба байгууллага бүрийн нэр сонголт болж харагдана.
9. **Хэзээ** байгууллагыг сонгоход, **Тэгвэл** тухайн байгууллагын нэрээр апп-уудад нэвтэрнэ (AC 1). Профайлд байгууллагын нэр, тэмдэг харагдана.
10. «Хувийн горим руу буцах» нь claim-гүй token руу шилжинэ.
11. Апп нэвтрэх үед байгууллагын горимыг шаардаж болно (`prompt=select_org`).

## Хязгаарын тохиолдлууд
- Хэрэглэгч байгууллагын горимд байхад байгууллагаас хасагдах: дараагийн token сэргээлтэд хувийн горим руу шилжиж, мэдэгдэл очно.
- Баталгаажаагүй байгууллага (NAV-029 хүлээгдэж буй): `org_verified=false`. Төлбөр, POI-ийн «баталгаажсан» үйлдэл хаалттай.
- Хүүхэд 2 эцэг/эхтэй: эцэг/эх тус бүрийн хүсэлтэд тухайн хүүхэд гарна.

## Хамрах хүрээнээс гадуур
- Апп-уудын өөрсдийн эрхийн матриц (тухайн апп хариуцна).
- SCIM-ээр гадны байгууллагын директорт синк хийх.

## Нээлттэй асуултууд
1. Hamuga ID одоо OIDC-ийн ямар claim, `scope` дэмждэг вэ? (ICT Group)
2. Webhook уу, эсвэл апп үе үе асуух уу? *Зөвлөмж: webhook, нэмээд token сэргээлтэд дахин шалгах.*
